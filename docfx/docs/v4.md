# About 4.0.0

`Dynamitey.Community` 4.0.0 is the first release of this continuation. The package id is `Dynamitey.Community`. The original `Dynamitey` package on NuGet remains upstream's 3.0.3, and installing that package does not get you this code.

Jay Tuley wrote Dynamitey. Upstream's last release was 3.0.3 in November 2023. The work below is what changed between that tree, marked by the `upstream-baseline` tag, and this release.

## The last release for .NET Framework

**4.0.0 is the last `Dynamitey.Community` release that supports .NET Framework.**

This package targets `netstandard2.0` and `net10.0`. `netstandard2.0` is the target a .NET Framework 4.6.1 through 4.8.1 project can reference. `net40` is already gone, which is why the version is 4.0.0 rather than 3.0.4.

On 6 May 2019 Microsoft published [".NET Core is the Future of .NET"](https://devblogs.microsoft.com/dotnet/net-core-is-the-future-of-net/). That post says .NET Framework 4.8 is the last major version of .NET Framework, and that further investment in the runtime and the base class library goes to modern .NET. Framework is still serviced as a component of Windows, including 4.8.1 (9 August 2022). It does not receive the new BCL APIs.

Releases after 4.0.0 target supported .NET LTS and STS versions only. They will not target `netstandard2.0`. Dropping that target is what lets the library call BCL APIs that .NET Standard 2.0 does not have. The plan for that line is [#95](https://github.com/dynamitey-community/dynamitey/issues/95): `net10.0` (LTS, supported through November 2028) and `net11.0` (STS). An application that has to stay on .NET Framework stays on `Dynamitey.Community` 4.x.

## Tests

The upstream tree had 219 tests. 4.0.0 runs **852**, which is 633 more, with 0 failed, 0 skipped, and no category filter. That count is the suite for this release.

## Brought current

- **Targets.** `net40` is dropped. `net10.0` is added. `netstandard2.0` stays for this release only, as described above.
- **Identity.** `PackageId` and `AssemblyName` are `Dynamitey.Community`. The root namespace stays `Dynamitey`, so existing source keeps compiling after the package reference changes.
- **Version.** GitVersion computes the version from tags. There is no version constant in the tree. 4.0.0 is the tag.
- **Package.** Repository URL, license, and readme are this project's. Source Link and a `.snupkg` are on. The strong-name key is this fork's own key. Copyright keeps the Ekon Benefits line and adds the community line.
- **Public surface.** Nullable reference types are on. Dynamic entry points carry `RequiresUnreferencedCode` and `RequiresDynamicCode`. The public API is frozen, and 4.0.0's surface is recorded in `PublicAPI.Shipped.txt`.
- **CI.** Build and test on Linux, macOS, and Windows, coverage floors on the shipped assembly, CodeQL on the library, NuGet audit, dependency review, a DocFX site, an AOT smoke test, and a benchmark compile. The inherited publish step that targeted another organization's feed is gone. Publishing uses a short-lived NuGet credential from GitHub OIDC, not an API key stored in the repository.
- **Tests and benchmarks.** NUnit 4. The 291 `ClassicAssert` calls use `Assert.That`. Benchmarks are BenchmarkDotNet and no longer fail CI on a wall-clock threshold. The three process-wide call-site maps are concurrent dictionaries.

## Cleanup

A CodeMaid pass over the library, tests, benchmarks, and the support fixture removed **98 unused `using` directives** and sorted the ones that remained. That pass is the formatting of the tree. Two edits it got wrong were put back: `private protected` on the cross-assembly accessibility tests, and the attribution notes on the Clay factory tests and on `List.Contains`, `IndexOf`, and `Insert`.

Other debt that was safe to remove is gone with it. The unused internal type `DummmyNull` is deleted. Four `catch` handlers that caught every exception now catch the exceptions those calls actually throw. Commented-out code and unused locals that the analyzers flagged are gone. Orphaned build files from the old tree are gone.

What remains in the analyzer backlog is written down in the project file, with a reason. Those findings stay because fixing them would change behavior or the public shape, including `CA1851` on a single-pass sequence in `Tupler`.
